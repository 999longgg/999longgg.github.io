Product Detail · QMStudy v2.4

QMStudy_web Interactive Quantum Mechanics Platform

Built on the knowledge spine of Quantum Mechanics: From Conceptual Foundations to Modern Applications, QMStudy_web is a modular digital textbook that links the concepts, equations, derivations, and physical experiments of every lesson through interactive animations. It ships with an AI tutor verified by QuanLLM-v2.0-qm and quanllm-harness (text selection, then follow-up in multi-turn dialogue), plus a same-origin adaptive study module for mastery tracking, error return, review tasks, and learning reports.

Product Features

What QMStudy Does

From reading to asking, from practice to review, every step lives on the same site and is backed by the same service and verification pipeline.

AI Tutor (QuanLLM-v2.0)

Select any textbook text and a small capsule appears next to the cursor (✨ Explain / 💬 Ask); clicking it opens a panel in the bottom-right corner for continuous follow-up. It supports SSE streaming, thinking stages grouped per agent, a process timeline, stop generation, and retrying the previous question. Text selected inside an AI answer can also be quoted and followed up.

Why is the ground-state energy of an infinite square well not zero?
Because the wavefunction must vanish continuously at the walls, that boundary condition admits only standing-wave solutions; the n=1 standing wave carries the smallest non-zero momentum, so a zero-point energy is unavoidable.

16-Lesson Modular Textbook

Preface, lessons 1–16, and an appendix, with body text, key concepts, equations, and interactive animations mapped one-to-one.

30 Interactive Experiments

Canvas-based numerical experiments: blackbody radiation, the photoelectric effect, double-slit interference, wave-packet evolution, tunneling, oscillators, hydrogen, the Bloch sphere, Bell correlations, and more.

🦉 Guided Mode

Socratic questioning: instead of handing over the answer, the tutor gauges understanding, asks back, and offers only the next hint. Say "just give me the answer" at any time to skip it.

Local Accounts and Records

Register and sign in inside the browser; passwords are stored only as local SHA-256 digests, and accounts plus learning records stay in this browser's localStorage.

Progress, Study Time, Certificates

Opening a lesson marks it as learned; the top bar shows a progress bar, lesson count, and cumulative study time. Finishing all 16 lessons unlocks a 🏆 certificate you can print or save as PDF.

Adaptive Study and Error Return

Mastery tracking, mistakes returned into the study loop, review-task scheduling, learning reports, and a strategy lab — same process, same port, same account as the textbook.

Knowledge Graph Mode

A second entry point beside the textbook: Cytoscape.js draws the concepts of all 16 lessons and their prerequisites, colouring nodes by six knowledge domains and grading them by mastery.

Selectable Equations and Notes

MathJax renders with CHTML output so equations in the text and in AI answers support character-level selection; selected text can be saved into per-lesson notes, edited, and exported as Markdown.

Server-Side Verification (quanllm-harness)

Every question runs through lct-unv/quanllm-harness: routing → dual solvers → synthesis → claim extraction → tool evidence → formal/requirement review → independent adjudication → targeted repair. Each question is verified independently and returns a verified or degraded status. The model can call built-in SymPy, mpmath, operator-algebra, dimensional, boundary, angular-momentum, and numerical tools, so it computes instead of guessing.

AI Tutor · Verified Pipeline

Answers Are Not Just Generated — They Are Verified

The browser only calls same-origin endpoints; the model and tools do their reasoning and verification on the server. Responses stream into the tutor panel over SSE, and thinking is grouped per agent instead of interleaving with the answer.

QMStudy_web · AI chain
🧠 model QuanLLM-v2.0-qm (QMSTUDY_AI_MODEL in .env, falls back to QuanLLM-v1.0-qm)
🛡️ pipeline quanllm-harness: controlled agents + quantum tools + claim-level verification + targeted repair
🔌 provider AI provider abstraction (ai/providers/); server.py does not import harness directly
🔑 api_key read server-side from the root APIKEY file; never exposed to the browser
📡 endpoint browser → same-origin /api/ai/answer (SSE) → harness
🧩 Endpoint overview
text
GET /api/ai/providers Current provider and availability POST /api/ai/answer Ask a question (SSE: thinking stages and final answer) GET /selftest/api/* AI self-test module API (isolated from the textbook /api/*) GET /api/docs API docs in development mode (disabled in production)

💡 Verification status: verified when every issue raised by the model has been cleared; verified_with_input_ambiguity when only ambiguity originating in the user's own input remains; degraded_delivery when an answer is still delivered but infrastructure or protocol requirements were not met.

Getting Started

Run the Whole Workbench Locally

Lesson content is fetched dynamically, so you cannot simply open index.html — browsers block local fetch. Use the bundled FastAPI service, which serves the site and proxies the AI.

Install and start
🐍 runtime Python 3.11 / 3.12 recommended
🌐 port server.py defaults to 127.0.0.1:8765 (--port to change)
🖥️ entries textbook / · self-test /selftest/ · report /strategy/report · graph /strategy/graph · lab /strategy/lab
💻 Quick start
bash
cd QMStudy_web python -m pip install -r requirements.txt python -m pip install -r requirements-ai.txt # AI backend (full quanllm-harness install) python server.py # defaults to 127.0.0.1:8765 # then open http://localhost:8765, register or sign in, and start learning
Credentials

First-Time Credentials (Required After Clone)

The repository ships no real API keys. Create the following files from their templates in the project root. The two AI modules use separate credentials — do not mix them.

Credential files (copy from the example template, then paste the real key)
File to create Copy from Purpose
.env .env.example Port, model, and other general configuration
APIKEY APIKEY.example Textbook AI tutor (quanllm-harness pipeline)
selftest/.env selftest/.env.example AI self-test module configuration
selftest/APIKEY selftest/APIKEY.example AI self-test module (non-streaming, thinking disabled)

🔑 API key format (per the quanllm-harness README): create an APIKEY file in the project root containing only the key itself — no quotes, no variable name, no export. If APIKEY is missing, the service falls back to QMSTUDY_AI_API_KEY in .env; when neither exists the AI endpoints return 503 while lessons and everything else keep working.

⚙️ One-click run (Windows): double-click install_and_start.bat the first time (it creates .venv, installs requirements, runs local diagnostics, and starts the service); afterwards just double-click start.bat. PowerShell users can run .\install_and_start.ps1 / .\start.ps1.

🔒 Security boundary: the account system is a local private account meant only to separate learning records between people sharing one machine and browser — it is not real server authentication. The server hosts static files plus /api/ai/answer only: no sessions, no cookies, no database. The endpoints are designed for local use, so add your own access control before exposing them to a LAN or the internet, otherwise anyone can spend your AI quota. Credential files are excluded by .gitignore; never share them or make the repository public.
