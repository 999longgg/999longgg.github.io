# 产品详情页（product.html / product.en.html）· 设计说明

> 交付物：`产品详情页面/product.html`（中文版）、`产品详情页面/product.en.html`（英文版），
> 样式在 `CSS/`、脚本在 `JS/`
> 内容来源：`产品详情页面/README.md`（QMStudy_web v2.4）
> 对应主页区块：`quanllm_update_v3/index.html` → `<section class="teaching" id="product">`
> 本说明不改动任何原有文件；主页与 `README.md` 均保持原样。

## 一、设计依据：以 CSS 差异为准的两版对照

按要求先对两版主页做了逐规则的样式差异分析，结论直接决定了实现方式：

| 文件 | 对比结果 |
| :--- | :--- |
| `styles.css` | **新版是旧版的严格超集**：旧版 313 个选择器在新版全部存在，**0 条规则被修改、0 条被删除**；新版只新增了「详细信息」下拉菜单相关规则（`.nav-dropdown`、`.details-toggle`、`.details-caret`、`.details-menu` 及其 hover / is-open 态） |
| `theme.css` | 两版 **完全相同**（SHA-256 一致） |
| `theme.js` | 两版 **完全相同**（SHA-256 一致） |
| `main.js` | 新版同样是超集：旧版逻辑一行未改，末尾追加了 `initDetailsDropdown()`（点击展开/收起、点击外部与 Esc 关闭、菜单内点击不冒泡） |

也就是说：**"导航栏等不同之处"的差异，全部集中在新增的下拉菜单上**，其余样式（含 `.hero-branch`、`.branch-banner`、`.about-card`、`.feature-card`、`.terminal-window`、`.apply-section`、`.demo-*`、`.cta-card-branch`、`.nav-sub` 等所有 v1.0.2-theme 页面用到的类）在新版中一字未动。

由此确定实现方式：**页面骨架沿用 v1.0.2-theme 的 `v1-0-qm.html`，样式与脚本使用主页的那一套文件**（复制到本目录的 `CSS/`、`JS/`，见第四节，内容与主页逐字节一致）。这样"保持原风格"由 HTML 结构保证，"导航栏与新版本一致"由同一份 CSS/JS 保证。

## 四、文件结构：CSS 与 JS 各自独立成文件

HTML 里**没有任何内联 `<style>` 或内联脚本**（页面运行时 `<head>` 中出现的那个 `<style>` 是 `main.js` 为滚动动画动态创建的，不在源文件中）。

```text
产品详情页面/
├── product.html          中文版页面（只保留结构与文案）
├── product.en.html       英文版页面
├── CSS/
│   ├── styles.css        复制自 quanllm_update_v3/styles.css（一字未改，SHA-256 一致）
│   ├── theme.css         复制自 quanllm_update_v3/theme.css（一字未改）
│   └── product.css       本页补充样式（两个页面共用）
├── JS/
│   ├── main.js           复制自 quanllm_update_v3/main.js（一字未改）
│   └── theme.js          复制自 quanllm_update_v3/theme.js（一字未改）
├── README.md             原有产品说明（未改动）
└── 产品详情页-说明.md      本文件
```

加载顺序为 `styles.css` → `theme.css` → `product.css`，因此页面级规则可以正常覆盖共享样式。

> **与主页的关系**：`CSS/styles.css`、`CSS/theme.css`、`JS/main.js`、`JS/theme.js` 是主页文件的副本，复制时已校验哈希一致。主页更新后，重新复制这四个文件即可同步：
>
> ```powershell
> $v3='..\quanllm_update_v3'; $d='.'
> copy "$v3\styles.css" "$d\CSS\styles.css"
> copy "$v3\theme.css"  "$d\CSS\theme.css"
> copy "$v3\main.js"    "$d\JS\main.js"
> copy "$v3\theme.js"   "$d\JS\theme.js"
> ```
>
> 好处是详情页可以整目录独立部署、不依赖 `../quanllm_update_v3/` 是否存在。

## 五、CSS/product.css 的内容

公共样式表没有覆盖到的部分集中在这一个文件里，全部使用主题令牌（`--surface-*`、`--border`、`--text-muted`、`--radius`、`--shadow`），因此**暗色 / 浅色主题自动适配**，也不会污染主页。文件内按 7 段组织：

1. **Hero 标题换行** — `.hero-branch .hero-title .gradient-text { display: block; width: fit-content; margin: 0 auto }`。主页 `.hero-title` 使用 `text-wrap: balance`，会把"量子力学"从中间拆成"量子 / 力学"两行；改为让渐变色标语独占一行、渐变背景贴合文字宽度。
2. **`#ai` 区块标题单行** — `#ai .section-header { max-width: 960px }`（详见第六节第 2 条）。
3. **`.workbench-grid`** — 5 个入口在 `min-width: 1100px` 时排成一行 5 列；窄屏不生效，自动回落到 `.about-grid` 原有的响应式断点（4 / 2 / 1 列）。
4. **`.entry-path`** — 入口路径胶囊（`/`、`/selftest/`、`/strategy/graph` …）。
5. **`.qm-table` / `.qm-table-wrap`** — 课程表和凭据表。公共 CSS 无任何 `table` 规则，这里补齐卡片式圆角、`surface-1` 表头、行悬停、`min-width + overflow-x` 横向滚动；首列 `nowrap`，但用 `html[lang="en"]` 让英文课名可以换行（*Lesson 2 · Wave–Particle Duality and Probability Waves* 很长）。
6. **`.topic-list`** — 附录行的多行专题列表（详见第六节第 3 条）。
7. **`.pipeline` / `.pipeline-step`** — 八阶段核验流水线标签。

## 六、本次三项调整

### 1. 样式与脚本独立成文件

原先写在页面内的 `<style>` 已全部提取到 `CSS/product.css`，并新建 `CSS/`、`JS/` 两个文件夹；两个页面只保留结构与文案。HTML 体积从 39.7 KB / 41.9 KB 降到 36.0 KB / 38.2 KB，`product.css` 为 6.5 KB。

### 2. `#ai` 区块标题恢复单行

- 原因：主页 `.section-header` 有 `max-width: 720px`，而标题「答案不是直接给出来的，而是核验过的」18 字 × 44px ≈ 792px，超出后末尾的「的」字被挤到第二行。
- 处理：只对本区块放宽 —— `#ai .section-header { max-width: 960px }`。
- 结果：桌面端实测标题宽 960px、高 70px，**行数 = 1**；窄屏仍按容器宽度正常换行（390px 手机上为多行，属正常表现）。
- 英文版一并放宽；英文标题 *Answers Are Not Just Generated — They Are Verified* 较长，在 960px 下自然排成 2 行。

### 3. 课程表附录行改为多行列表

- 原因：附录行的交互动画内容原是一长串（70 字符）单行文本，独占整列，使「交互动画」列被撑到 866px，与首列形成 285 : 866 ≈ 1 : 3 的失衡比例（这就是"这一列太空"的来源）；而其余 16 行内容都很短。
- 处理：把 7 项内容改成 `.topic-list`（`<ul>` + `display: grid` 两列布局、带主题色圆点），窄屏（≤700px）自动变单列。
- 结果（中文版实测）：列表 2 列 × 4 行、单元格高 144px；表格列宽重新分配为 **424 : 726 ≈ 1 : 1.7**，比例明显协调。
- 英文版同样处理（英文条目更长，2 列 × 4 行、列表高 161px）。
